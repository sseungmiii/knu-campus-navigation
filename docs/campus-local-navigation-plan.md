# 크누패스 전용 교내 시설·보행로

작성일: 2026-10-30 (한국 시각)
상태: 구현 설계 기준. 승인 후 진행한 1차 구현 범위와 남은 사항은 [staging-setup.md](staging-setup.md)를 참고한다. 운영 DB는 변경하지 않는다.
대상 프로젝트: knu-campus-app.

## 목표

카카오·네이버 검색에 없는 교내 시설을 크누패스에 직접 등록하고, 이를 지도 검색·수업 장소·길찾기 목적지로 사용할 수 있게 한다. 직접 확인한 교내 통로와 지름길을 도보 경로에 반영하고, 해당 이동 시간을 수업 출발 시각 역산에 포함한다.

## 사용자 추가 설명: 강의실 안내를 우선

사용자의 핵심 목표는 **강의실 위치를 찾고 그 강의실까지 이동하는 안내**다. 일반 편의시설 등록보다 강의실·층·출입구·건물 간 연결통로를 우선한다. 아래 1~3차는 기능 의존 관계이며, 실제 첫 적용 대상은 한 강의실과 그 강의실에 도달하는 동선으로 좁힌다.

사용자가 제공한 첫 동선 후보:

1. IT1호관으로 들어간다.
2. 엘리베이터로 3층에 이동한다.
3. **3층 서편 출입구**로 나간다. (사용자 추가 설명)
4. 2호관·5호관 쪽으로 연결된다.

이는 사용자 제공 경로 설명이며 아직 완성된 보행로 데이터가 아니다. IT1의 진입 출입구·엘리베이터 위치·사이드문 위치, 2호관과 5호관 각각의 도착 층/출입구, 두 방향의 분기 지점·중간 구간·역방향 이용 가능 여부·개방 시간을 확인해야 한다. 설명만으로 두 건물 모두에 같은 층의 구름다리가 직접 이어진다고 단정하거나 좌표를 생성하지 않는다.

첫 목적 강의실은 사용자가 지정한 **IT1호관 306호**다. 실제 호실의 층·엘리베이터에서 호실로 이어지는 복도 위치는 별도 확인한다. 306호 안내에 3층 서편 출입구 밖으로 나가는 동선을 무조건 넣지 않는다. 강의실 접근 동선과 2·5호관으로 통과하는 동선을 별도 분기로 등록한다.

### 카카오 길찾기와의 연결 방식

연계는 크누패스 안에서 수행한다. 카카오로 확인 가능한 도보 구간을 연결 지점까지 조회하고, 그 뒤 검증된 자체 교내/실내 구간을 이어서 지도·단계 안내·소요 시간으로 제공한다. 카카오 지도 위에 자체 경로선을 표시하는 것과 카카오 길찾기 데이터 자체를 수정하는 것은 다른 작업이다. 크누패스에 등록한 통로가 카카오맵 앱/웹의 공식 길찾기 결과에 자동 반영되는 것으로 설명하지 않는다.

- IT1 306호가 목적이면: 외부 출발지 → 확인된 IT1 출입구(기존 카카오 경로) → 확인된 엘리베이터·층·복도 → 306호(크누패스 자체 안내).
- 다른 건물로 이동할 때 IT1 통과가 유효하면: 카카오 경로 → IT1 진입 → 엘리베이터로 3층 → 서편 출입구 → 확인된 연결 구간 → 목적 건물/강의실. 이 경로는 해당 연결 구간 확인 후 후보로 제공한다.
- 교내 통로를 지난 뒤 다시 외부 보행로로 나오면 그 지점에서 목적지까지의 카카오 구간을 연결할 수도 있다. 각 구간 접점이 실제로 이어지는지 확인한다.
- 카카오 구간 시간 + 자체 실내/교내 구간 시간 + 여유 시간을 같은 선택 경로에 합산한다. 엘리베이터 시간은 평면 직선거리로 계산하지 않고 층 이동·대기 추정 또는 실측 시간을 사용한다.
- 최초에는 '크누패스 교내 경로' 후보를 제공하고 확인된 구간끼리 비교한다. 보행망이 충분하지 않은 상태에서 학교 전체의 절대 최단 경로라고 표현하지 않는다.

공식 지도 표시 기능 참고: [카카오 지도 Polyline](https://apis.map.kakao.com/web/documentation/#Polyline). 실제 경로 조합·층 안내·시간 합산은 크누패스에서 구현해야 한다.

첫 사용 흐름:

- 강의실명/번호와 건물 약칭으로 검색한다. 같은 호실 번호가 여러 건물에 있으면 건물·층을 함께 골라 구별한다.
- 현재 출발지에서 목적 강의실에 접근할 수 있는 출입구/연결통로까지 길찾기를 한다.
- 실내는 'IT1 진입 → 엘리베이터 → 3층 → 사이드문 → 확인된 연결통로 → 목적 강의실' 같은 순서 카드와, 확보한 경우 층별 약도로 안내한다.
- 각 단계의 층·문 이름·방향·현장 사진/랜드마크를 등록할 수 있게 한다. 사용자가 '해당 층 도착' 등으로 직접 단계를 진행할 수 있게 한다.
- 실내 현재 층·정확한 GPS 위치의 자동 추적은 초기 완료 조건에 넣지 않는다.
- 강의실은 건물 입구 좌표만 저장하는 것으로 완료하지 않는다. 층·호실과 확인된 접근 동선이 있어야 '강의실까지 안내'로 표시한다.
- 미확인 통로를 거쳐야 하는 강의실은 확인된 출입구까지의 안내와 미확인 실내 구간을 구분한다.

확장 방법: 건물별 출입구·계단·엘리베이터·층간 연결을 공통으로 등록하고, 각 강의실은 해당 층의 복도/갈림길에 연결한다. 강의실마다 외부 출발지부터 전체 경로를 중복 작성하지 않는다. 실제 층별 배치 자료가 없으면 호실 번호만으로 위치·층·복도 방향을 추정하지 않는다.

첫 완료 기준: 실제 강의실 하나를 검색·시간표에 등록하고, 검증된 건물/층 이동 단계로 강의실까지 안내한다. 이동 시간 측정 전에는 시간 추정과 미확인 구간을 명시한다. 사용자가 제공한 IT1 3층 동선은 목적 강의실 접근에 유효한지 확인한 뒤 경로 후보에 포함한다.

## 현재 확인한 상태

- 실제 도보 경로는 server/routing.cjs의 카카오 조회 결과를 사용한다.
- 장소 검색도 같은 파일의 카카오 장소 검색 결과를 반환한다. 교내 전용 시설 검색을 합칠 지점이다.
- src/campus-data.js의 노드·지름길에는 시연용 데이터라는 설명이 있다. 현장 검증 없이 실제 안내 데이터로 승격하지 않는다.
- 지도는 별도 iframe이며 시간표와 메시지를 주고받는다. 검색 결과만 추가하는 데서 끝내지 않고 목적지 시설 ID·선택 출입구·내부 이동 정보까지 전달해야 한다.

## 1차: 직접 등록한 시설을 검색하고 목적지로 사용

운영자가 지도에서 위치를 찍고 이름·별칭·건물·층·호실·시설 종류를 등록하는 관리 화면을 만든다. 일반 사용자에게 공개되는 것은 검토 후 공개한 항목이다. 초기에는 운영자 등록을 우선하고, 학생 제보는 이후 별도로 받는다.

시설 데이터:

- 고유 시설 ID, 이름, 검색 별칭·약칭
- 시설 종류: 강의실, 열람실, 프린터, 정수기, 휴게실 등
- 건물 ID, 층, 호실, 지도 표시 좌표
- 사용할 출입구 ID와 찾아가는 설명
- 이용 시간·휴무·일시 폐쇄 여부, 출처·확인일·공개 상태

층이 다른 시설이 같은 지도 좌표를 공유할 수 있으므로 좌표를 시설 ID로 사용하지 않는다. 건물 중심 좌표와 실제 보행 출입구 좌표도 구분한다.

검색과 화면:

- 크누패스 내부 시설 검색 결과를 카카오 검색 결과와 함께 반환하고, 내부 이름·별칭 정확 일치를 우선한다.
- 내부 검색은 외부 장소 검색 실패나 결과 없음과 독립적으로 동작한다.
- 결과에 '크누패스 교내 시설', 건물·층·호실을 표시한다.
- 상단 지도 검색, 길찾기 출발·도착 검색, 시간표 강의 장소 검색에서 같은 내부 시설을 사용할 수 있게 한다.
- 학교 내부 탭에서도 검색·종류 필터·마커 표시를 제공한다.
- 길찾기는 선택한 출입구까지 연결하고, 시설까지의 내부 안내를 별도 단계로 표시한다. 내부 통로를 아직 등록하지 않았다면 상세 실내 경로를 제공하는 것처럼 표시하지 않는다.

1차 완료 조건: 외부 지도에는 검색되지 않는 실제 시설 하나를 직접 등록하고, 별칭 검색 → 목적지 선택 → 출입구까지 길찾기 → 내부 안내 → 시간표 장소 등록을 같은 시설 ID로 완료한다.

## 2차: 교내 보행로·지름길을 수동 등록

관리 화면에 시설 등록과 별도로 길 등록 도구를 둔다. 지도에 여러 점을 찍어 실제 보행선을 그리고 출입구·갈림길·다른 보행로에 연결한다. 건물이나 벽을 가로지르는 단순 직선은 보행로로 자동 생성하지 않는다.

보행망 데이터:

- 노드: 출입구, 갈림길, 계단·엘리베이터 입구, 층별 연결 지점
- 구간: 시작·끝 노드, 실제 꺾임점 좌표, 거리, 방향, 보행 유형
- 조건: 계단·경사·실내 여부, 층 이동, 이용 가능 시간, 폐쇄 상태
- 검증: 확인일·출처·검토 상태, 공개/비공개
- 이동 시간: 거리·보행 속도 기반 추정 또는 확인된 실측 시간. 계단·엘리베이터 대기 등 별도 가산을 구분한다.

운영자는 미리보기에서 연결 단절·잘못된 층 연결·반대 방향·출입 시간 조건을 확인한 뒤 공개한다. 폐쇄된 통로나 미검증 지름길은 경로 후보에서 제외한다. '지름길'이라는 이름만으로 항상 우선 선택하지 않고 전체 이동 시간·조건으로 비교한다.

2차 완료 조건: 실제 확인한 통로 하나를 등록해 연결 상태·방향·운영 조건에 따라 사용 여부가 달라지고, 지도와 단계별 안내가 같은 보행선을 표시한다.

## 3차: 외부 경로 + 교내 경로 + 수업 출발 계산

- 학교 밖 이동은 기존 공급자 경로를 유지한다.
- 교내 이동은 검증된 자체 보행망으로 계산하고, 외부 경로와 연결이 확인된 출입 지점에서 이어 붙인다.
- 다른 출입구가 효율적이면 전체 이동 시간을 비교해 안내한다. 가까운 좌표라는 이유만으로 벽·울타리를 통과하는 연결선을 만들지 않는다.
- 자체 보행망이 불완전한 경우 제공 가능한 기존 경로와 미확인 구간을 명시한다. 막힌 구간을 임의 좌표로 메우지 않는다.
- 건물 간 실외 경로와 실내 층·통로 안내를 구분한다. 실내 GPS로 현재 층과 호실을 자동 식별한다고 가정하지 않는다.
- 등록된 내부 이동 시간이 있으면 기존 일괄 내부 이동 가산과 중복 계산하지 않는다.
- 출발 시각 = 수업 시작 - 외부 이동 - 교내/실내 이동 - 도착 여유.
- 지도에 그린 경로, 시간표에 표시한 이동 시간, 출발 시각은 같은 선택 결과를 사용한다.

3차 완료 조건: 등록 시설을 수업 장소로 선택하면 검증된 교내 구간을 포함한 경로와 출발 시각이 일치한다. 통로를 폐쇄하면 해당 구간이 제외되고 시간이 다시 계산된다.

## 구현 전에 확보할 실제 자료

첫 대상은 시설 1~2개와 지름길 1개로 좁힌다.

- 시설: 이름·별칭, 건물, 층·호실, 실제 접근 가능한 출입구, 위치를 확인할 수 있는 정보
- 지름길: 시작·끝, 중간에 통과하는 지점, 계단·층 이동 여부, 이용 가능 시간과 방향
- 확인되지 않은 내용은 미확인으로 남긴다. 운영자가 지도에서 점을 지정할 수 있게 하므로 사용자가 좌표 숫자를 직접 알아야 하는 흐름으로 만들지 않는다.

## 다음 구현 작업 범위

큰 기능이므로 main에 바로 작성하지 않고 codex/feature-campus-local-navigation 계열 기능 브랜치에서 진행한다. 실제 브랜치 생성 전 기존 Git 상태와 같은 이름의 브랜치를 확인한다.

먼저 1차를 끝까지 연결하고 실제 시설로 검증한 뒤 2·3차로 확장한다. 인증·저장은 기존 회원 시간표와 별도로 운영자 쓰기/공개 시설 읽기 권한을 설계한다. 운영 DB 변경은 실제 구현 단계에서 해당 범위와 정책을 확인한 후 진행한다. 데이터 모델이나 관리 화면만 만든 상태를 지름길 안내 완료로 보고하지 않는다.
