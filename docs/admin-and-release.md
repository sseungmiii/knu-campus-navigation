# 관리자 로그인과 운영 반영

## 현재 기능

일반 회원의 Supabase 시간표 인증과 분리된 전용 관리자 계정 1개를 서버 설정으로 지정한다. 공개 회원가입이나 `user_metadata`, localStorage의 관리자 플래그로 권한을 부여하지 않는다. `/campus-lab`은 서버에서 검증된 관리자 세션이 있어야 열리고, 미설정·비로그인·위조·만료 세션은 로그인으로 이동한다. 시설 저장·수정·삭제·파일 불러오기·내보내기 및 양식 자동 보관 전에 서버의 관리자 세션을 재확인한다. 지도 시설 관리 링크도 관리자에게만 표시한다.

시설 데이터는 사용자가 선택한 **기기 초안 저장** 방식이다. 공용 DB에 시설을 게시하는 API는 아직 없다. 브라우저 저장 공간 자체는 기기 사용자가 제어할 수 있으므로, 이 초안을 서버가 승인한 공용 시설 목록으로 간주하지 않는다. 이후 공용 저장을 추가할 때는 DB 쓰기에도 서버 관리자 권한 및 공개 승인 정책을 적용해야 한다. 이번 작업은 운영 DB·일반 회원 인증을 변경하지 않는다.

## 관리자 계정 지정 방법

1. 테스트 사이트 `/admin/setup`을 열고 원하는 관리자 아이디·비밀번호·확인을 입력한다. 실제 비밀번호는 사용자 본인이 입력하며 채팅에 보내지 않는다. 아이디는 영문·숫자·`_`·`-` 3~40자, 비밀번호는 12자 이상 256바이트 이내다. 길고 다른 서비스와 겹치지 않는 비밀번호를 사용한다.
2. **설정 파일 만들기**를 누르고 테스트용·본 사이트용 파일을 각각 내려받는다. 브라우저에서 PBKDF2-SHA256 검증값과 별도 난수 세션 키를 생성하며 비밀번호 원문은 전송·파일 저장하지 않는다.
3. 각 Vercel 프로젝트의 Environment Variables에 파일 안의 세 항목을 Secret으로 등록한다. 테스트 파일은 `knu-campus-navigation-test`, 본 사이트 파일은 `knu-campus-navigation`에 사용한다. 두 고정 주소 모두 해당 프로젝트의 Production 환경을 선택한다. 관리자 설정은 Preview에 복제하지 않는다.
4. 세 항목: `KNU_ADMIN_USERNAME`, `KNU_ADMIN_PASSWORD_HASH`, `KNU_ADMIN_SESSION_SECRET`. 기존 지도·버스·날씨·Supabase 설정은 유지한다. 파일은 Git에 추가하지 않는다. `.env.*`는 이미 제외돼 있다.
5. 테스트를 재배포하고 `/admin/login`에서 로그인한다. 관리자 계정 생성은 Vercel 설정 등록 및 재배포를 마쳐야 완료된다. 일반 회원가입으로 관리자 계정을 만들 수 없다.

설정 파일을 잃었거나 비밀번호를 바꾸려면 관리자 로그인 후 `/admin/setup`에서 새 파일을 만든다. 로그인할 수 없는 경우에는 소유자가 로컬에서 같은 생성 도구를 실행하거나 Vercel에서 기존 관리자 설정을 제거·재설정한다. 일반 사용자는 이 페이지에서 서버 계정을 바꿀 수 없다. 설정 변경은 해당 환경 재배포 후 적용된다.

## 세션과 보호 범위

- `iron-session` 9.0.1의 암호화 쿠키, 8시간 만료, HttpOnly·Secure·SameSite=Lax·Path=/·도메인 미지정. 개발 모드만 비보안 쿠키를 쓴다. 실제 비밀번호·검증값·세션 키는 클라이언트 번들에 전달하지 않는다.
- 서버가 계정명·권한·발급/만료 시각·환경·현재 비밀번호 버전을 확인한다. 테스트와 운영 세션 키를 분리하고 환경도 검사한다. 계정명/비밀번호 검증값 변경은 기존 세션을 만료시킨다. 쿠키 삭제 로그아웃이며 개별 탈취 토큰의 서버 목록 기반 폐기는 아직 없다. 긴급 전체 폐기는 세션 키를 회전하고 재배포한다.
- 로그인·로그아웃·수정 권한 확인은 동일 출처 요청만 허용한다. 로그인 본문은 4KB로 제한하고, 오류에 비밀번호나 제공기관 정보를 노출하지 않는다. 인스턴스 내 IP별 15분 6회 제한은 보조 수단이며 분산 환경 전체 제한을 보장하지 않는다. 공용 운영 확대 시 Vercel Firewall 또는 공유 저장소 기반 제한을 추가한다.

구현 기준: [iron-session 공식 사용법](https://github.com/vvo/iron-session#usage), [OWASP 비밀번호 저장 지침](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

## 운영 반영 절차

검증 기록(2026-10-30): 코드 검사·전체 테스트·격리 배포 빌드가 통과했다. 일회용 로컬 계정으로 실제 Next 서버 및 브라우저의 로그인·시설 저장·로그아웃·다른 열린 탭에서 삭제 차단을 확인했고 검증 시설을 삭제했다. 실제 사용자 관리자 설정은 아직 등록하지 않았으므로 배포 환경의 관리자 로그인 확인은 설정 후 수행해야 한다.

테스트는 `staging`, 운영은 `main`을 유지한다. 이번 기능은 `codex/feature-facility-admin`에서 개발하고 검증 후 staging으로 반영한다. 운영 Vercel은 main에 연결된 상태를 보존한다.

1. `npm ci`, `npm run check`, `npm test`, `npm run build`. Node 22.13+ 필요, Vercel은 24.x 사용.
2. 비밀키 없는 격리 빌드에 `node scripts/verify-admin.cjs <빌드 폴더>`를 실행한다. 일회용 계정으로 실제 Next 서버의 로그인·위조/비로그인 차단·CSRF·로그아웃을 확인한다. 실제 관리자 자격증명은 사용하지 않는다.
3. 테스트 관리자 설정·재배포 후 `node scripts/release-check.cjs https://knu-campus-navigation-test.vercel.app`를 실행한다. 관리자 설정이 없으면 종료 코드 2로 대기 상태를 표시하며 운영 배포를 실행하지 않는다.
4. 실제 관리자 로그인 → 시설 추가/수정/삭제/파일 내보내기 → 로그아웃 → 일반 브라우저에서 등록 화면 접근 차단을 확인한다. 일반 회원의 시간표도 실제 운영 반영 전에 확인한다.
5. main 대상 PR에서 시설 분류·핀·관리자 보호와 환경 격리 변경을 검토한다. 본 사이트 관리자 설정을 Production에 준비한 다음 PR을 병합하면 기존 Git 연동으로 본 사이트에 배포된다. 현재 요청은 준비이므로 자동 병합·운영 승격하지 않는다.
6. 배포된 main 커밋과 운영 고정 주소에서 같은 읽기 검사를 실행한다. 문제 시 운영 Vercel에서 직전 정상 배포로 되돌리고 수정은 staging에서 진행한다. DB 마이그레이션은 이번 릴리스에 없다.

## 추가하면 좋은 관리자 전용 기능

우선순위는 시설 제보 검토·공개 승인, 운영시간/휴무/출입 제한 관리, 중복 시설 병합 및 일괄 등록, 변경 이력·복구, API 상태·사용량 확인 순서다. 공개 시설 DB와 이력 저장소가 준비되면 공용 등록으로 확장한다. 일반 회원의 개인 시간표 접근 권한은 시설 관리와 분리한다.
