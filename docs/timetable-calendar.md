# 주간 시간표와 수업 길찾기

수업은 시작·종료 시각의 분을 5분 단위로 선택한다. 시작 시각을 변경하면 종료 시각이 75분 뒤로 맞춰지며 이후 직접 조정할 수 있다. 자정을 넘기는 기본값은 같은 날 23:55로 제한하며 종료가 시작보다 늦어야 저장된다. 이전의 분 단위 수업을 수정할 때에는 가까운 5분 단위로 맞춘다.

`주 2회 수업 추가`를 누르면 두 번째 요일과 시간을 독립적으로 정한다. 공통 수업명·학기·장소로 한 번의 INSERT를 사용해 두 회차를 함께 저장한다. 어느 한 회차가 유효하지 않거나 RLS에 걸리면 전체가 저장되지 않는다. 저장 후 각 요일의 수업을 개별 수정·삭제한다.

월~금 캘린더는 학기별로 표시하며 같은 과목은 같은 색을 쓴다. 겹치는 수업은 가로로 나누고 주말 수업은 아래 요일 목록에서 관리한다. 저장하면 캘린더 상단으로 돌아가 결과를 알리고 저장한 요일을 선택한다. 운영 저장 점검에서는 별도 검증 계정으로 POST → GET 재조회 → 검증 행 삭제를 확인했다. 기존 사용자의 저장 실패는 재현되지 않았으며 모든 원인을 해결했다고 단정하지 않는다.

수업을 누르면 다음 수업 일시를 기준으로 이동을 준비한다. 즐겨찾기가 없으면 현재 위치를 요청하고 실패하면 출발지 검색을 안내한다. 경로를 조회하면 상단에 출발 마감, 이동 시간, 실내 이동·여유 시간을 표시한다. 출발 마감은 예상값이며 배차·교통 상황에 따른 도착 보장이 아니다.

조회된 경로의 `이 경로 즐겨찾기`는 해당 수업의 출발지 좌표·이동 수단·보행 조건·대중교통 노선 식별 정보·예상 소요와 여유 시간을 저장한다. 사용자의 명시적인 저장 전에는 GPS 위치를 Supabase에 저장하지 않는다. 다음 선택에서는 저장된 예상 출발 시각을 즉시 보여주고 같은 조건으로 최신 경로를 다시 조회한다. 동일 대중교통 노선이 없으면 다른 경로임을 알린다. 과거 버스 도착 정보나 경로 선을 실시간 정보로 재사용하지 않는다. 실제 GPS 추적 안내는 별도의 안내 시작 버튼을 눌러 시작한다.

## 배포

`supabase/migrations/20261022155625_class_route_favorites.sql`은 기존 시간표 테이블에 크기 제한이 있는 nullable JSONB 열만 추가한다. 기존 소유자 RLS와 데이터는 유지한다. API는 검증된 사용자 ID로만 갱신한다. 이 마이그레이션을 적용한 뒤 앱을 배포한다. 공개 키 기반 사용자 요청과 PostgreSQL 테스트로 검증한다.

## 날씨 제안

지도 위에는 경북대 기준 기온·강수 상태·갱신 시각을 작은 카드로 표시하고, 수업 이동 화면에는 출발 전후 시간의 강수 예보와 우산 안내를 표시하는 편이 유용하다. 처음부터 사용자의 정밀 위치를 날씨 조회에 전송할 필요는 없다.

기상청 단기예보 조회서비스의 초단기실황과 초단기·단기예보를 서버에서 조회하고 캐시한다. 공공데이터포털 활용 신청과 서비스 키가 필요하다. 키는 서버 환경변수에만 둔다. 비가 온다는 이유로 확인되지 않은 실내 연결 경로를 추천하지 않으며, 비 예보와 실제 통행 가능한 지름길 데이터는 분리한다. 이번 배포에는 날씨 API 연결이 포함되지 않았다.
