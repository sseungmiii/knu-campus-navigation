# 크누패스 구현 순서와 확인 기준

`docs/product-spec.md`를 기준으로 기존 지도 시제품을 확장한다. 아래 순서는 개발 우선순위이며 새로운 완료일이나 API 사용 계약을 약속하는 일정은 아니다. 신청서에 기재된 개발 기간은 2026-10-01~10-31이다.

## 1 시간표와 오늘 수업

작업: 시간표 입력·수정·삭제 화면과 브라우저 저장, 건물·강의실 입력, 한국 시간의 오늘 수업 선택, 현재 수동 드롭다운과 연결.

코드 위치: 신규 시간표 모듈과 화면, `src/app.js`의 calculateDeadline 연동.

확인: 새로고침 후 시간표 유지, 수업 없는 날 안내, 여러 수업 정렬, 한국 날짜 경계, 잘못된 시각 입력 거부. 원래 지도·모달·재생 기능 유지.

## 2 경로 데이터와 목적지

작업: 단일 좌표 배열을 노드·링크 데이터로 확장, 목적지 강의실과 출입구·층 연결, 핵심 건물과 지름길 현장 검증, 출처·운영시간 기록.

코드 위치: `src/campus-data.js`, 신규 경로 탐색 모듈. 먼저 소수 건물의 검증 가능한 경로부터 구현.

확인: 경로가 끊긴 목적지에 임의 경로를 만들지 않음, 양방향·단방향 처리, 운영시간 밖 링크 제외, 동일 출발·도착점 및 계단·엘리베이터 구간 처리.

## 3 경로 선택과 출발 시각

작업: 최단 시간·체력 온존·지름길 선택, 구간별 예상 시간, 교통·층 이동·선택 경유시간을 분리한 출발 계산, 선택 경로에 맞춘 단계 카드.

확인: 09:00 수업 + 교통 25분 + 캠퍼스 7분이면 08:28. 카페 대기 5분을 추가하면 08:23. 선택 조건에 맞는 경로가 없으면 안내. 자정 이전 출발은 전날로 표시. 계단과 엘리베이터 선택에 따라 시간·안내가 함께 변경됨.

## 4 동선 주변 생활 정보

작업: 경로 30~50m POI 필터, 편의점·화장실·프린터 데이터 추가, 식당 미니 카드, 기존 학식 프로젝트 JSON 연동과 식당 id 매핑.

확인: 날짜·식당 매핑이 맞는 메뉴만 표시, API 실패와 미등록 상태 구분, 메뉴 없는 식당 카드 유지, 가까운 POI·멀리 떨어진 POI의 거리 필터 확인. 운영시간 미확인은 미확인으로 표시.

## 5 위치 기반 페이스메이커

작업: 사용자 선택에 따른 위치 권한 요청, 실제 위치를 경로에 투영, 남은 거리·수업까지 남은 시간으로 권장 페이스 계산, 기존 재생 모드 유지.

확인: 권한 거부·위치 오차·경로 이탈 처리, 도착·시간 초과 상태 구분, 재생·일시정지·초기화 유지. 실제 내비게이션과 시연 애니메이션이 화면에서 구분됨.

## 6 AI 경유 요청과 제보 확장

작업: 핵심 기능 완료 후 자연어 의도 구조화와 도구 호출용 백엔드, 경유 요청에 따른 POI 선택·대기시간 재계산. 제보는 검토 후 데이터 반영하는 별도 확장으로 다룸.

확인: AI 실패 시 기존 계산 사용, 구조화 결과 검증, 없는 장소 거부, 숫자 계산은 계산 모듈 결과만 사용, 프론트엔드 비밀키 없음.

## 배포와 작업 방식

- 수정은 독립 저장소 `knu-campus-navigation`에서 진행한다.
- `npm run dev`로 로컬 실행 후 `npm run check`, `npm test`를 실행한다.
- 화면 변경은 모바일과 데스크톱에서 지도·컨트롤·모달을 확인한다.
- `main` 반영 후 GitHub 자동 검사와 Pages 배포 완료를 확인한다.
- 신청서 원본과 참가자의 연락처·학번·서명 등은 공개 저장소에 포함하지 않는다.

첫 구현 단위는 1단계 시간표 등록과 오늘 수업 자동 선택으로 잡는다. 지도 엔진 전환이나 외부 API 도입은 필요한 기능과 데이터 공급자가 확정된 뒤 진행한다.


## 2026-10-10 진행 순서 조정

사용자 요청으로 길찾기·선택 경로 기반 페이스메이커·겹치지 않는 UI를 시간표보다 먼저 구현한다. 카카오맵 공식 도보 REST API 접근이 성공했으므로 지도 제공업체는 유지한다. REST 키는 로컬 서버 환경변수에 보관하고, 서버 배포 전까지 로컬에서 개발한다. 다음 구현은 시간표 등록과 실제 경로 소요시간 기반 출발 계산이다.

## 2026-10-10 시간표·Supabase 구현

기존 카카오 지도와 경로를 유지하면서 Next.js에 Supabase Auth/SSR 및 시간표 CRUD를 추가한다. 요일·시각·학기 기간·강의 장소를 등록하고 오늘의 다음 수업을 지도 목적지로 연결한다. 두 사용자만 각자 소유한 시간표에 접근하도록 DB RLS를 적용하며 Secret Key를 사용하지 않는다. SQL 파일은 준비하되, 사용자가 테스트 계정 지정을 뒤로 미뤘으므로 허용 목록은 비워 둔다. 실제 프로젝트의 SQL 적용과 두 계정 로그인·저장 검증은 별도 설정 단계다.
